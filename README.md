# Atlas

Atlas is a lightweight persistent memory extension for [pi](https://pi.dev/).
Package source and runtime memory are deliberately separate:

- this repository contains the public extension and tests;
- `${ATLAS_ROOT:-$HOME/.atlas}/memory/` contains private runtime memory.

**Memory is not part of this repository.** Never copy, commit, publish, or share
`~/.atlas/memory/` unless you have reviewed it as sensitive data. The existing
`projects.md` plus `knowledge/index.csv` layout remains supported; no migration
of a private memory bank is required.

## Behavior

- Adds a **bounded** selection of `projects.md`, current/daily context,
  matched private project context, and triggered knowledge as an `atlas_memory`
  system prompt section before an agent turn. Pi records the section in the
  session transcript and appends only a delta when it changes, so earlier
  messages stay provider-cacheable.
- Reports each injected source and why it matched. Knowledge matching is
  case-insensitive and segment-aware (`pi` does not match `spinning`).
- Uses the current working directory, prompt terms, and optional private aliases
  to select project/workstream context.
- Exposes `atlas_read`, `atlas_update`, and `atlas_search` tools.
- Rolls a stale `daily.md` into `history/daily/` before creating a fresh daily
  stub. The archive copy is synced before the working file is reset.
- Provides `/atlas-status` and a non-destructive `/atlas-compact` workflow.

Atlas never indexes the whole memory bank and never injects an unbounded file.
If a context budget is reached, it says so; use `atlas_read` for a specific
bounded file.

## Privacy and provider disclosure

Atlas files stay local **until Atlas injects or returns their contents**. Injected
memory becomes the `atlas_memory` section of pi's system prompt, recorded in the
session transcript, and `atlas_read` results become tool messages. Pi sends that
context to the currently selected model provider (and to any proxy/gateway
configured for that provider), subject to that provider's retention and privacy
policy. `/atlas-status` notifications and the private `config.json` itself are
not intentionally sent to the model, but config-selected context is.

Atlas performs no network requests and has no telemetry. It reads only beneath
the configured memory root. Project `paths` are matching metadata; Atlas does
not read files from those project paths. Keep secrets out of memory that should
not be disclosed to the active provider.

## Runtime location and compatible layout

`ATLAS_ROOT` defaults to `~/.atlas`, preserving the original private runtime
location:

```text
~/.atlas/memory/
├── projects.md
├── daily.md
├── current.md                 # optional; generated by /atlas-compact
├── config.json                # optional, private matching configuration
├── knowledge/
│   ├── index.csv
│   └── reference.md
├── projects/                  # optional project-specific context
│   └── example.md
└── history/daily/
```

Override the private root before starting pi if needed:

```bash
export ATLAS_ROOT="$HOME/.atlas"
```

Paths passed to Atlas tools must be relative to `memory/`. Atlas fails closed
when its static checks find lexical traversal, absolute paths, NUL bytes, or a
symbolic link in a memory path. Final components are opened with `O_NOFOLLOW`;
Atlas also holds and rechecks the parent directory's device/inode identity around
path-based operations. See the concurrent-filesystem limitation below.

## Existing projects and knowledge files

`projects.md` remains a bounded global project index. The knowledge CSV format
is also unchanged and supports quoted commas and escaped double quotes:

```csv
filename,description,triggers
reference.md,"General reference","reference term, alternate phrase"
```

Each CSV record must occupy one physical line. Embedded newlines inside quoted
fields (multiline RFC 4180 records) are deliberately unsupported and produce a
clear error rather than being parsed ambiguously. At most the configured number
of knowledge files is injected for a prompt. Match metadata identifies the
trigger(s) that selected each file, and search rendering is bounded by the tool
read limits.

### Private aliases, paths, and workstreams

Aliases and local checkout paths belong in the optional private
`memory/config.json`, not in this public package. This allows project-aware
retrieval without publishing personal paths or names:

```json
{
  "projects": [
    {
      "name": "Example Project",
      "aliases": ["example-app"],
      "paths": ["~/src/example"],
      "workstreams": [
        { "name": "API", "aliases": ["backend lane"] }
      ],
      "context": ["projects/example.md"]
    }
  ]
}
```

- `paths` match the current working directory with path-segment boundaries.
- Project names/aliases and workstream names/aliases match prompt boundaries.
- `context` entries are memory-relative files loaded only for a matched project.
- Missing configuration is valid; Atlas continues to use `projects.md` and the
  knowledge index exactly as before.
- Invalid private configuration or an unsafe selected path fails closed with a
  clear Atlas warning.

## Safe writes and bounds

`atlas_update` uses an atomic same-directory temporary-file rename for
replacement. It fsyncs replacement contents before rename and fsyncs the parent
directory after rename on filesystems where Node supports directory fsync.
Append operations use both an in-process queue and an exclusive lock file, open
the destination in append mode, and add separators so cooperating writers'
entries cannot run together. Successful appends always end with a newline.

Atlas never reclaims a lock based only on its age: a slow live writer is allowed
to finish. A write times out rather than stealing an existing lock. If a process
crashes while holding one, inspect its recorded PID and remove the indicated
`.atlas.lock` file manually only after confirming that writer is gone.

Defaults are intentionally conservative:

| Setting | Default | Environment variable |
|---|---:|---|
| Tool read output | 50 KiB | `ATLAS_MAX_READ_BYTES` |
| Tool read lines | 2,000 | `ATLAS_MAX_READ_LINES` |
| One update | 256 KiB | `ATLAS_MAX_INPUT_BYTES` |
| One update lines | 4,000 | `ATLAS_MAX_INPUT_LINES` |
| Final file | 1 MiB | `ATLAS_MAX_FILE_BYTES` |
| Final file lines | 20,000 | `ATLAS_MAX_FILE_LINES` |
| Total injected context | 24 KiB | `ATLAS_MAX_CONTEXT_BYTES` |
| Total context lines | 400 | `ATLAS_MAX_CONTEXT_LINES` |
| One injected source | 8 KiB | `ATLAS_MAX_SOURCE_BYTES` |
| One source lines | 120 | `ATLAS_MAX_SOURCE_LINES` |
| Knowledge matches | 3 | `ATLAS_MAX_KNOWLEDGE_MATCHES` |
| Write-lock wait | 5,000 ms | `ATLAS_LOCK_TIMEOUT_MS` |
| Path characters | 1,024 | `ATLAS_MAX_PATH_LENGTH` |

Compaction also accepts `ATLAS_COMPACT_SECTION_LINES` (default 20) and
`ATLAS_COMPACT_RECENT_LINES` (default 40). All overrides must be positive
integers. Per-source limits cannot exceed total context limits; read and update
limits cannot exceed file safety limits; compaction line settings cannot exceed
the update line limit. Generated `current.md` output is additionally truncated
to the smaller update/final-file byte and line bounds.

The lock serializes cooperating Atlas processes that use the same local
filesystem and lock path; it is not a distributed-filesystem lease. Successful
writes sync file data, and replacements/new files sync their parent directory
where supported, but ultimate persistence still depends on the operating system,
filesystem, and hardware.

Node does not expose portable `openat`/`renameat` operations relative to a held
directory descriptor. The `O_NOFOLLOW`, canonical-path, and parent-identity
checks therefore close ordinary/static symlink escapes and detect common swaps,
but they cannot eliminate an adversarial process continuously swapping ancestor
directories between path-based syscalls. Keep the memory root mode private and
do not place it in a directory writable by untrusted users.

## Daily current-state workflow

Raw history and concise state serve different purposes:

1. Append durable events to `daily.md`.
2. Run `/atlas-compact` when daily context becomes noisy.
3. Atlas writes an exact raw snapshot under
   `history/daily/snapshots/` and atomically refreshes `current.md`.
4. `daily.md` is **not modified** by compaction.

The deterministic summary keeps bounded entries from `In Progress`,
`Key Decisions`, `Blockers`, and `Next Steps`. If none exist, it keeps a bounded
recent window. No model is called, so compaction does not invent or reinterpret
facts. Review or edit `current.md` normally if a hand-curated state is better.
When `current.md` exists, Atlas injects it plus a bounded head-and-tail window of
recent `daily.md`; otherwise it injects the bounded daily window alone.

## Install

From a local checkout:

```bash
pi install ~/src/pi-atlas
```

Or configure it as a pi package in `~/.pi/agent/settings.json`:

```json
{
  "packages": ["~/src/pi-atlas"]
}
```

A published Git package can be installed with its repository URL. Installing
package source never includes the separate private memory directory.

Restart pi after package changes, or use pi's `/reload` command.

## Development

Requires Node.js 22.19.0 or newer, matching the pinned pi 1.4.0 dependencies' engine
requirement (`systemPromptOptions.sections` needs pi 1.4.0 or newer):

```bash
pnpm install
pnpm test
pnpm typecheck
```

Tests use temporary memory roots and cover traversal/symlink rejection, atomic
and concurrent writes, bounds, trigger/project matching, and non-destructive
compaction. Tests never read `~/.atlas/memory/`.
